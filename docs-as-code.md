# Docs-as-Code: Example Workflow

## Overview

This example illustrates how Markdown documentation can be managed alongside software changes in Git.

## Suggested Workflow

1. Review the product requirement or Jira ticket.
2. Create or update the relevant Markdown file.
3. Check the draft against the verified source.
4. Submit changes through a branch or pull request.
5. Review terminology, links, formatting, and accuracy.
6. Approve and publish the documentation.

## Example Change Record

- Change: Add report export instructions
- Source: Fictional requirement REP-101
- File: samples/user-guide.md
- Review status: Demonstration only

## Benefits

- Keeps documentation changes trackable.
- Supports peer review.
- Makes revisions easier to compare.
- Helps align documentation updates with product changes.

## Scope

This is a proposed example workflow. It does not represent a configured CI/CD pipeline or an automated publishing system.
